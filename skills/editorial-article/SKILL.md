# Editorial HTML Article

## Use when

- the primary deliverable is a long-form web article;
- converting a URL, document, PDF, Markdown, transcript, or notes into an editorial page;
- creating a visual essay, explainer, tutorial, briefing, or archive.

Do not use for dashboards, forms, applications, or ordinary marketing pages.

## Intake

Confirm:

- source material;
- target audience;
- target language;
- article type;
- intended information retention;
- output format;
- asset permissions.

If no source or outline exists, request it. Do not invent the subject matter.

## Phase 1: normalize the source

- Preserve the original.
- Convert content into structured Markdown.
- Record extraction gaps and low-confidence regions.
- Preserve code, formulas, citations, tables, and terminology.
- Translate only when requested, keeping a source version for comparison.

## Phase 2: editorial plan

Create one plan covering:

- brief and reading goal;
- audience and tone;
- information-retention target;
- outline and section purpose;
- hierarchy and density;
- theme and layout width;
- table of contents;
- image and diagram plan;
- optional cover concept.

Confirm material editorial decisions before full production.

## Phase 3: first spread

Build:

- optional cover;
- opening viewport;
- lead or summary;
- first section;
- one representative visual block.

Review the first spread for direction, readability, density, asset fit, and mobile behavior. Repair it before scaling the system across the article.

## Phase 4: full build

- Use semantic article structure.
- Keep a coherent component and type system.
- Give each section a clear reading job.
- Preserve source meaning and required information.
- Use tables, code, diagrams, and interactive elements only when they improve understanding.
- Keep interactions optional to the reading path.
- Support print and offline use when required.

## Phase 5: review

### Editorial

Check accuracy, retention, structure, voice, repetition, and citations.

### Visual

Check hierarchy, rhythm, line length, density, image treatment, and mobile reading.

### Technical

Check semantics, links, assets, accessibility, print, performance, and standalone behavior.

Repair the smallest causal section and rerun the affected review.

## Delivery

Deliver the final article and a short note stating source coverage, information retention, language handling, assets, and any unresolved extraction limits.
