# Product Copy

## Use when

- writing new website or product copy;
- improving existing copy;
- defining positioning, audience, differentiation, or brand voice;
- creating headlines, labels, calls to action, error messages, or metadata.

## Step 1: build context

Reuse an existing product context when available. Otherwise gather only what the task needs:

- product category and actual function;
- primary audience and task;
- problem and current alternatives;
- supportable differentiation;
- customer language;
- objections;
- voice and forbidden terms;
- proof points;
- primary action.

Do not invent missing details. Mark a precise information need instead.

## Step 2: diagnose the edit

- New or generic input: build the argument from verified facts.
- Real voice present: preserve its vocabulary, emphasis, rhythm, and position.
- Point edit: change only the requested line and the minimum surrounding context.

State the mode internally before drafting so the scope does not drift.

## Step 3: draft in units

Break the work into named units such as headline, support line, CTA, section heading, body, proof, and error state. Draft alternatives only for the units where choice is useful.

Run each line through three questions:

1. Can the reader picture what this means?
2. Can the claim be proven true or false?
3. Could a competitor use the same line unchanged?

Rewrite lines that fail. If evidence is absent, remove the claim or request the evidence.

## Writing rules

- Prefer clear language over clever phrasing.
- Use active voice and concrete nouns and verbs.
- Keep one idea per sentence and one job per section.
- Make benefits traceable to actual features.
- Keep claims specific and supportable.
- Match the user's language and level of formality.
- Use utility language in dashboards and operational surfaces.
- Make CTA labels describe the action and result.
- Error messages explain the problem and next step.
- Keep terminology consistent through actions and feedback.

## Avoid

- fabricated statistics, testimonials, customers, awards, or guarantees;
- empty superlatives and technology buzzwords;
- generic calls to action;
- contrast formulas such as "not X, but Y";
- stacked negation lists;
- self-answered rhetorical questions;
- trailing clause pileups;
- em dashes in generated copy;
- excessive capitalization, bold text, quotation marks, emoji, or exclamation marks;
- filler sections, FAQ entries, and proof blocks.

## Editing passes

Use only the passes the task requires:

1. clarity;
2. voice and tone;
3. reader consequence;
4. evidence;
5. specificity;
6. appropriate emotional texture;
7. friction and next action.

After editing, revert changes that are only different rather than measurably better.

## Output contract

For a point edit, return changed lines and a short reason. For page copy, organize by section and identify any missing evidence. Do not bury the final copy under long commentary.
